# AGENTS.md

## Purpose

Instructions for coding agents working in `packages/webrtc`.

## Scope

* Applies to `src`, `tests`, `tools/wpt-runner`, and package-local docs.
* This package is the main public WebRTC API (`RTCPeerConnection`, media, data channel).
* Optional `werift/polyfill` (`src/polyfill`) installs browser globals and `getUserMedia` via required `mediaRegister`; `peerConnectionConfig` supplies per-install PC defaults, and fixed-codec register tracks constrain rather than expand PC capabilities. An empty array supplies plain empty audio/video tracks. It is not re-exported from `src/index.ts`. Node TypeScript without DOM uses `werift/polyfill` for constructor globals; DOM-lib projects should import `werift/polyfill/dom`. On Node it also complements a missing or `Node.js/<major>` `navigator.userAgent` with a Chromium-compatible value. Existing non-Node User-Agents are kept unless `userAgent` is passed.
* Lower-level protocol packages (`ice`, `dtls`, `rtp`, `sctp`, `common`) are dependencies; prefer fixing protocol bugs in those packages when the root cause lives there.
* Upstream WPT harness code lives under `tools/wpt-runner/` and must not leak stricter shims into default `src` behavior. WPT creates every `RTCPeerConnection` with the browser-compatible configuration in `tools/wpt-runner/browserConfig.ts` (`compatibility: "standard"`, so every compatibility option is `"standard"`); the regression gate is `wpt/baseline.json` (rules in `tools/wpt-runner/baselineLogic.ts`: a lower status or an unreported baseline subtest regresses; a target that only regressed by timeouts is rerun once with longer timeouts).

## Do

1. Prefer package-local validation (`npm test`, `npm run type`) before workspace-wide commands.
2. Keep Arrange helpers reusable; memleak Arrange utilities live in `tests/memleak/heapUtils.ts` and scenario setup in `tests/memleak/scenarios.ts`.
3. Add Japanese comments in Act / Assert phases when operation order or expectations are not obvious.
4. When adding package scripts, update this guide's Commands table in the same change.
5. Keep memleak tests out of the default vitest suite (`vitest.config.mts` excludes `tests/memleak/**`). The leak property (`tests/pbt/leak`) is deterministic and stays in `npm test`, each test with `retry: 0`; its heap-slope part (P3) runs only with `WERIFT_NEGOTIATION_LEAK_HEAP=1` (`npm run pbt:deep`).
6. For negotiation changes (`negotiationTransaction.ts`, description apply paths in `peerConnection.ts`, `src/negotiation/*`, router / receiver / sender tables), the implementation and the tests are the source of truth: the invariant, phases, signaling transitions, per-subsystem mutation timing and snapshot owners are the TSDoc of `NegotiationTransaction` (`src/negotiationTransaction.ts`), and each rule is documented at the code that implements it and verified by a test. Record a new or changed rule there and in a test. A pending description may add routing keys but must not change a key the current session uses (reject before mutation or stage until commit). Keep `assertNegotiationInvariants` in `tests/negotiation/harness/negotiationTransactionUtils.ts` able to detect a new class of state, and add a found failure as a deterministic case or a replayed seed. A test whose verdict is only invariants, unchanged state, continued traffic or a baseline match belongs to a property of `tests/pbt/scenario/negotiationScenarioProperty.test.ts` as a fixed scene (scenario text), not to a new individual test; a claim that holds after any operation sequence (traffic, JSEP transition, rollback, events, idempotence, trickle, RTCP feedback, selected pair, commit) belongs to an oracle of the model property (`tests/pbt/model/oracles.ts`), with the operations it needs in the generator of `model/generator.ts` (SDP rewrites on the wire in `model/wireMutations.ts`) and a found failure as a short operation list in `model/scenes.ts`; timing, concurrency, special environments and concrete ICE / DTLS / BUNDLE / RFC codec values stay individual tests. A case uses only descriptions and candidates werift creates itself: interoperability with browsers and other implementations (their SDP shapes, candidates such as mDNS) is the end-to-end tests' responsibility (`e2e/`), so do not fabricate another peer's description in `tests/negotiation/cases`. Negotiation tests live in `tests/negotiation/`: the shared infrastructure in `tests/negotiation/harness/` (Arrange helpers and `assertNegotiationInvariants` in `negotiationTransactionUtils.ts`, the case harness in `negotiationCase.ts`) and the cases in `tests/negotiation/cases/`. Property tests live in `tests/pbt/`: one directory per property test (negotiation: `fuzz/`, `scenario/`, `model/`, `leak/`; media TWCC / BWE / send path / receive path / simulcast RTX repair: `twcc/`, `bwe/`, `sender/`, `receiver/`, `simulcastRtx/`, each with its generator in `generator.ts`) drawing from the base every package shares, `packages/pbt` (the seeded random stream, the seed count / replay configuration and the deep search; its `README.md` states the rules every property test follows: directory, seed variables, titles, retry, coverage checks); keep a new property test in its own directory and list it in `tests/pbt/suites.ts`. The leak property keeps its Arrange and measurement in `leak/leakProbe.ts` and its fixed scenes and cycles in `leak/scenes.ts`; new session state gets a `leakFootprint` metric, and state kept on purpose gets an explicit bound documented at `BOUNDED_METRICS` in `leak/leakProbe.ts`. A remaining individual test is a TypeScript case of the harness (`describeCases` / `negotiationCase` with `ref`, Japanese `// Arrange:` / `// Act:` / `// Assert:` comments, description operations through `c.offer` / `c.setRemote` / ... so the invariants run after each; see the header of `tests/negotiation/harness/negotiationCase.ts`); table-driven matrices use the `negotiationTest` fixtures (`videoPeers`, `session`, `closing`) of `negotiationTransactionUtils.ts`, imported as `test`. Negotiation tests end with `expectSessionContinues` (next offer, ICE restart, added DataChannel / transceiver, offer from the peer, traffic); files that call `enforceSessionContinuation()` (every `describeCases` block does) fail a test that skips it without `exemptFromContinuation(pc, reason)` (`exempt` in a case's meta). A fix that changes behavior against `develop` must pass that helper and the develop comparison of Do 8.
7. Before requesting review of a negotiation change, run the deeper property searches with `npm run pbt:deep` (`packages/pbt`'s runner with the suites of `tests/pbt/suites.ts`; parallel; `--suite fuzz,scenario,model,leak`, `--seeds`, `--steps`, `--jobs`, `--heap-seeds`) — it runs the same searches as these single-process commands (the episode fuzzer `WERIFT_NEGOTIATION_FUZZ_SEEDS=300 WERIFT_NEGOTIATION_FUZZ_STEPS=20 npx vitest run tests/pbt/fuzz/negotiationTransactionProperty.test.ts` the scenario properties `WERIFT_NEGOTIATION_SCENARIO_SEEDS=300 npx vitest run tests/pbt/scenario/negotiationScenarioProperty.test.ts` and the model property `WERIFT_NEGOTIATION_MODEL_SEEDS=300 npx vitest run tests/pbt/model/negotiationModelProperty.test.ts -t seed`; `WERIFT_NEGOTIATION_SCENARIO_SEED` / `_STEPS` and `WERIFT_NEGOTIATION_MODEL_SEED` / `_STEPS` replay a printed seed and print a shrunk scene; the leak property replays with `WERIFT_NEGOTIATION_LEAK_SEED` / `_STEPS` / `_CYCLES`) and a self-review that lists every path writing live state while a description is pending. Run it against develop with `--baseline <temporary develop worktree>` (`git worktree add --detach`, dependencies linked or installed): a confirmed failure (it failed again alone) is replayed on develop with the same environment up to `--baseline-runs` (default 3) times, and one develop repeats in the same form (the same test and the same whole cause, or the same errors outside the test results; the rules are in `packages/pbt/README.md`) is reported as pre-existing and left out of the exit code; one develop passes, fails in another form or whose cause cannot be compared stays exit 1. Only the heap slope verdict of P3 (`STATISTICAL_FAILURE_MARKER`) is statistical: without `--baseline` it is reported as statistical, not as a failure, and with it, it counts unless the baseline fails the same way; every other P3 failure counts as usual. Read the closing `summary:` line (confirmed / pre-existing / flaky / statistical) in the review; there is no known-flake list, the baseline replay is the evidence. Thresholds are not loosened to pass. A value that is live while a description is pending follows the table in the TSDoc of `expectedLive` (`tests/negotiation/harness/negotiationTransactionUtils.ts`); encode a new rule there before changing the implementation.
8. A change to how created descriptions are applied later or again must keep the description reuse contract of `tools/negotiation-diff/scenarios.ts` (`--check` exits 1 on a mismatch): compare with develop locally with `tools/negotiation-diff` (procedure in the header of `run.ts`; never in the active worktree) and keep its difference count at 0. The runner draws configurations (including `asymmetric*`, a peer b whose codecs differ in payload type, fmtp or rtcp-fb; run them with `--configs <name>` for a codec negotiation change), application operations, close timings and peer mutations; `compare.ts` also fails on unsettled operations, `failed` connections without an injected fault and transceiver states that differ from develop.

## Don't

* Do not export SPED internals or add `IceOptions.sped`; enablement is `PeerConfig.sped` only.
* Do not run memleak as part of `npm test` / CI; use `npm run memleak` only.
* Do not enable vitest `retry` for memleak (hides leak failures).
* Do not silence leak detections; open a follow-up for root-cause fixes if a real leak is found.
* Do not keep negotiation design rules, spec-to-test maps or test migration tables in separate documents; they drift from the code. Put a rule in the TSDoc of its implementation and verify it with a test.

## Validation

* Logic changes in `src`: `npm run type` and relevant `npm test` paths.
* Changes that can alter what werift sends or accepts on the wire (ICE / STUN, DTLS, SCTP, RTP, SPED fallback): `npm run test:interop-develop` (this branch against `develop` in every offerer / answerer and DTLS client / server pairing; `tests/interop/develop` skips without `WERIFT_DEVELOP_ROOT`).
* Opt-in released Pion ICE agent fallback: `npm run test:pion-ice-agent` with `WERIFT_PION_ICE_AGENT` or `WERIFT_PION_ICE_AGENT_AUTO_BUILD=1`. Default `npm test` skips a missing path. The opt-in script fails if neither source is set, even when `packages/ice/tools/pion-ice-agent/pion-ice-agent` is already built (see that README for the explicit command).
* Opt-in Pion SPED interop (SPED changes): `npm run test:pion-webrtc-sped` with `WERIFT_PION_WEBRTC_SPED` (the harness built by `tools/pion-webrtc-sped/build.sh`, Docker). Default `npm test` skips it; the opt-in script fails without the variable. Chromium SPED is the e2e `npm run sped:ci`.
* Opt-in released werift interop (SCTP initiator, DTLS `[1.3, 1.2]` / SPED fallback to 1.2, ICE-TCP, DataChannel IDs with an older release; findings in `reviews/71cc0e0d-warp-webrtc-integration.md` (appendix B)): `npm run test:legacy-werift` with `WERIFT_LEGACY_RELEASE=<installed werift package dir>` or `WERIFT_LEGACY_RELEASE_AUTO_INSTALL=1` (installs `werift@0.26.0`, or `WERIFT_LEGACY_RELEASE_VERSION`, with `--ignore-scripts` into a temporary directory). Default `npm test` skips it; the opt-in script fails if neither is set.
* GCC / TWCC / bottleneck simulation changes: `npm run test:sim`, plus `cd e2e && npm run test:sim` when the Chrome path may be affected, and `cd e2e && npm run test:sim:netns` (needs Docker) when the estimator's response to a real Chrome receiver matters.
* TWCC feedback / BWE / sender send-path / receiver padding, `ReceiverTWCC` or RID-based RTX repair (the hole ledger of `receiver/nack.ts`, `mediaSsrcOfRtx` / `switchRidMedia` in `rtpReceiver.ts`) changes: the relevant `npm test` paths, plus `npm run pbt:deep -- --suite twcc,bwe,sender,receiver,simulcastRtx` before review; replay a failed seed with the environment variables printed in its test title.
* Negotiation changes: the full `npm test` (includes the negotiation property tests with their fixed scenes and regression seeds), plus the deeper property searches above before review, run with `--baseline` against a develop worktree; the review gate is `0 confirmed` in its `summary:` line (pre-existing failures are listed with the baseline's result; the P3 heap slope verdict is judged only against the baseline).
* Memleak harness changes: short smoke with reduced env (see `tests/memleak/README.md`), then optional full `npm run memleak`.
* WPT runner / allowlist / baseline: `npm run wpt`, repeated (10 full runs before changing `wpt/baseline.json`).

## Maintenance

* Keep this guide aligned with `package.json` scripts.
* When memleak scripts or artifact paths change, update `tests/memleak/README.md` and this Commands table together.
