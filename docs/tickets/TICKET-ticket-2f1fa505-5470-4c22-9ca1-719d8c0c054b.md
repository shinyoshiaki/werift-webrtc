## Problem
Downstream reports from SimpleIM and KTPInfrastructure describe process termination when network-interface enumeration fails in restricted Linux/systemd environments (including AF_NETLINK restrictions). The failure may propagate from ICE host-candidate/mDNS-related setup rather than being surfaced as a recoverable gathering error.

On current `develop`, `packages/ice/src/internal/hostInterfaces.ts` calls `os.networkInterfaces()` directly in both host-interface enumeration paths. This warrants checking the exception boundary and whether a thrown enumeration error can escape a callback/task.

## Expected behavior
- No uncaught exception or unhandled rejection from interface enumeration.
- Report a structured ICE gathering error, or safely continue with other viable candidate sources where possible.
- Do not silently report successful gathering when no usable candidates remain.
- Preserve predictable behavior when local interface enumeration is blocked.

## Suggested regression tests
- Stub `os.networkInterfaces()` to throw and assert that the ICE/RTCPeerConnection API reports failure without terminating the process.
- Exercise both interface-enumeration paths, with and without STUN/TURN configuration.
- Test a restricted Linux/container environment when feasible.

## Scope / caveat
The downstream failures are evidence of impact, not yet a minimal reproduction proving the root cause is in werift. PR #803 cancels pending mDNS lookups on close, but does not directly address interface-enumeration exceptions. Related general error-propagation request: #840.
