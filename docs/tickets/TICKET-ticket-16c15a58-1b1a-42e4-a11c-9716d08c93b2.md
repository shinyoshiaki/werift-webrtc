# RTCPeerConnection のデフォルトフォールバック STUN を無効化するオプション

## 元の description
peerconnection のコンストラクタでデフォルトフォールバッグのstunサーバーを無効化するオプションを追加する。

## 目的と背景
関連 Issue: #691, #774。`iceServers: []` や TURN のみの構成でも `stun.l.google.com:19302` へ問い合わせが走り、
意図しない外部通信・公開 IP 漏洩・STUN 応答が無い環境での最大 5 秒の待機が起きる。

## 変更内容
- `packages/ice`: `IceOptions.useDefaultStunServer`（既定 true）。false かつ `stunServer` 未指定なら STUN サーバーなし。
- `packages/webrtc`: `PeerConfig.iceUseDefaultStunServer`（既定 true、`RTCPeerConnection` コンストラクタで指定）を ICE へ伝播。

## 技術メモ
`Connection.applyStunTurnServersFromOptions` がフォールバックを適用。`mergeIceServerOptions` は他のフィールドを維持するため
`setConfiguration` / ICE restart でも設定が保たれる。既定値は後方互換のため true のまま。

## 完了条件
- `iceUseDefaultStunServer: false` で空/TURN のみ構成のとき STUN が使われない。明示 STUN は使われる。
- 既定動作は不変。`tests/integrate/defaultStun.test.ts` と `npm run type` が通る。
