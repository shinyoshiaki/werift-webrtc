## Summary

`RtpRouter.routeRtcp()` currently routes generic payload-specific feedback by `senderSsrc` first and only falls back to `mediaSsrc`.

For PLI/FIR this can deliver a keyframe request to the wrong stream in SFU / relay scenarios, because the RTCP packet sender SSRC identifies the feedback sender, while the media SSRC identifies the media source the feedback is about.

## Current behavior

Current develop code in `packages/webrtc/src/media/router.ts` has:

```ts
case RtcpPayloadSpecificFeedback.type: {
  const psfb = packet as RtcpPayloadSpecificFeedback;
  switch (psfb.feedback.count) {
    case ReceiverEstimatedMaxBitrate.count:
      ...
      break;
    default:
      recipients.push(
        this.ssrcTable[psfb.feedback.senderSsrc] ||
          this.ssrcTable[psfb.feedback.mediaSsrc],
      );
  }
}
```

This is unsafe for keyframe feedback.

In a relay, a viewer's RTCP sender SSRC may correspond to one of that viewer's own outgoing streams (for example microphone/camera). The PLI/FIR can therefore be delivered to that receiver rather than to the sender for the video stream named by `mediaSsrc`.

## Expected behavior

PLI and FIR should be routed according to the media source they target.

For PLI, that is `feedback.mediaSsrc`.

For FIR, please also verify the FCI semantics and target SSRC handling rather than applying the generic sender-first fallback.

## Downstream reproduction / workaround

Crocodile added a relay/SFU implementation and reproduced incorrect keyframe-request routing. It currently monkey-patches werift's private router so PLI/FIR are delivered by media SSRC:

https://github.com/pwalda/crocodile/pull/51

Current workaround:

https://github.com/pwalda/crocodile/blob/main/packages/relay/src/relay.ts

The workaround is roughly:

```ts
if (packet.type === 206 && (feedback.count === 1 || feedback.count === 4)) {
  const target = router.ssrcTable[feedback.mediaSsrc];
  if (target) return target.handleRtcpPacket(packet);
}
```

This made keyframe requests reach the intended forwarded video slot in their SFU.

## Suggested tests

Please add multi-stream tests where:

- RTCP sender SSRC belongs to stream A.
- PLI targets media SSRC for stream B.
- Only stream B's sender receives the PLI.

For FIR, add coverage matching the actual FIR FCI target semantics.

This is still present in upstream develop as of 2026-10-17.
